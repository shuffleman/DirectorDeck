# 共存规则：与其他 skill 一起生成剧本

本 skill 的定位是**交付适配层**。它假设主 agent 同时加载了其他创作 skill
（例如短剧/漫剧/小说/分镜 skill），并负责最后一步：把创作结果变成
DirectorDeck 可导入的剧本。

## 一、职责边界

| 谁负责 | 内容 |
|---|---|
| 其他创作 skill / 用户 | 题材、世界观、人物、人物弧光、剧情、爆点、文风、节奏、结局 |
| 本 skill | 分段、段长、画面/台词结构、`@图片N` 槽位、导入格式、格式校验 |
| 用户 | 最终取舍、目标平台、交付时长、素材槽、是否锁音/二采 |

**不要越界**：本 skill 不提供“短剧怎么写才好看”的创作规则；不重写剧情；
不擅自改角色名/关系/结局；不把其他 skill 的规则复制进本 skill 再判断一次。

## 二、触发不冲突

本 skill 的 `description` 只认 DirectorDeck 交付目标。以下泛词**不单独触发**：

- 写剧本、写小说、写短剧、写分镜、写故事、写台词；
- 帮我改剧情、想想人物、设计反转。

明确触发信号：

- `DirectorDeck` / `剧本导入` / `ScriptImport`；
- `@图片N` / 素材槽 / 自动匹配素材 / 锁音；
- `H3 V6` / `【第N段｜X秒】` / `第N段（X秒）`；
- “把这份剧本弄成能导入 DirectorDeck 的格式”。

如果用户同时说“用 X skill 写，再交给 DirectorDeck”，先让 X skill 创作，
再由本 skill 交付。不要反过来在本 skill 里从零创作。

## 三、冲突裁决顺序

1. **用户明确指令**；
2. **其他创作 skill 已确定的创作内容**（题材/角色/剧情/文风/结局）；
3. **本 skill 的导入格式与硬约束**（段头、时长、台词行、素材槽上限、段数上限）；
4. 两者不可兼得时：保留创作内容，改交付结构（拆段、拆句、加过渡），
   不删剧情、不改人物、不改结局。

### 典型冲突与正确做法

| 冲突 | 错误做法 | 正确做法 |
|---|---|---|
| 其他 skill 写了一场 20 秒的戏，DirectorDeck 目标段长 5 秒 | 删掉一半剧情 | 拆成 4 段；每段一个事件，段间保持连续 |
| 台词 30 字，但只有 5 秒 | 硬塞进去，TTS 说不完 | 拆成相邻两段，各 14–16 字；或压缩到核心信息 |
| 其他 skill 用 Markdown 表格/加粗 | 直接把 Markdown 塞进导入框 | 转成 DirectorDeck 文本；如需人类可读版另附 |
| 两个格式 skill 都要求输出 | 同时输出两套，用户分不清 | 明确标注“导入稿”和“人类可读版”；导入稿优先 |
| 素材库只有 2 张图，但剧本有 5 个角色 | 猜 `@图片3..5` | 只绑确认过的槽；其余不写 refs 让自动匹配或先问用户 |
| 其他 skill 定了角色名，DirectorDeck 导入器对名字有限制 | 改角色名 | 保留角色名；必要时用短别名做对白前缀，并注明映射 |
| 另一个 skill 也声明“负责最终格式” | 两边都改，格式打架 | 由主 agent 指定唯一交付层；本 skill 只做 DirectorDeck 格式 |

## 四、交接协议（主 agent 视角）

```
创作 skill（出故事/人物/分场）
        ↓  [交接包：见 handoff-schema.md]
本 skill（只做格式映射 + 校验 + 输出导入稿）
        ↓
DirectorDeck_ScriptImport → 视频生成器链
```

- 创作 skill 完成前，不要启动本 skill 的交付流程；
- 本 skill 完成后，不要再让创作 skill 重写全文；如需改剧情，回到创作 skill 改，
  再重新交付，避免“格式层偷偷改内容”；
- 交接包中要明确“哪些已定、哪些可调”，本 skill 只调后者。

## 五、输出层的命名隔离

- 本 skill 名称固定为 `directordeck-screenplay-bridge`，不使用 `screenwriter`、
  `story`、`drama`、`novel` 这类通用名，避免和已有 skill 重名；
- 本 skill 只读取、不写入项目文件；校验脚本默认只输出报告；
- 如用户要求保存文件，使用用户指定路径；没有指定时不要擅自创建工程目录。

## 六、单独使用时的最小兜底

如果没有任何创作 skill，用户仍要求“写一个能导入 DirectorDeck 的剧本”：

1. 先问或确认：题材、总时长/段数、角色数、可用素材槽；
2. 用最小结构补足：目标 → 障碍 → 转折 → 钩子；
3. 明确告诉用户“这是最小交付稿，创作层没有其他 skill 参与”；
4. 不要假装自己是完整的编剧规则库，也不要编造素材槽。
