# DirectorDeck 剧本交付桥

本 skill 是**交付适配层**，不是创作规则库。

它只做四件事：

1. 把别的 skill（或用户）给的剧本草稿，整理成 DirectorDeck `DirectorDeck_ScriptImport` 能直接吃的外部剧本；
2. 把创作稿映射成“段 → 秒数 → 画面 → 台词 → `@图片N` 素材槽”的可拍摄结构；
3. 校验导入格式、分段连续、台词长度、素材槽越界；
4. 在多个 skill 同时启用时，只补格式和交付契约，不改写其他 skill 已定的内容。

## 一、什么时候用 / 不用

### 用

用户明确要把剧本交给 DirectorDeck，或目标里出现以下信号：

- `DirectorDeck`、`剧本导入`、`ScriptImport`、`分段生成`；
- `@图片N`、`素材槽`、`自动匹配素材`、`锁音`；
- `H3 V6`、`【第N段｜X秒】`、`第N段（X秒）` 这类交付格式；
- 用户已经和别人/别的 skill 写好一版剧本，要求“整理成能直接导入 DirectorDeck 的版本”。

### 不用

以下情况**不要**启用本 skill，交给其他 skill：

- 只是“写一个剧本/短剧/小说/分镜”，没有 DirectorDeck 交付目标；
- 需要世界观设定、人物弧光、题材文风、爆点节奏等创作判断；
- 只是讨论剧情、改台词创意，而不需要可导入 DirectorDeck 的文件；
- 用户明确要求其他平台的格式（如标准剧本 PDF、分镜表 Excel），且不提 DirectorDeck。

> 触发词只认“DirectorDeck 交付目标”，不认“剧本/小说/分镜”这类泛词。这是为了避免和其他创作 skill 抢触发。

## 二、共存契约（最高优先级）

与其他 skill 一起使用时，按下面的优先级裁决：

1. **用户明确指令**最高；
2. **其他创作 skill 已经确定的题材、世界观、角色、剧情、文风、节奏**——保留，不改写；
3. **本 skill 的 DirectorDeck 交付格式、分段/时长、台词长度、素材槽约束、输出纪律**——只在交付层生效；
4. 本 skill 不重复、不覆盖其他 skill 的创作规则；其他 skill 也不应覆盖这里的导入格式。

冲突处理：

| 情况 | 处理 |
|---|---|
| 其他 skill 的角色名/关系/设定与本 skill 的分段冲突 | 保留角色与剧情，只调整段数和切分位置 |
| 台词太长，放不进目标秒数 | 拆句/拆段，不删剧情、不改台词含义 |
| 其他 skill 要求 Markdown 剧本格式 | 交付 DirectorDeck 导入格式；如需展示，可额外给“人类可读版”，但必须明确哪份是导入稿 |
| 两个 skill 都要输出格式 | 以用户的交付目标为准；没有明说时，优先 DirectorDeck 导入格式 |
| 用户要求本 skill 也负责创作 | 可以补最小结构（目标/障碍/转折/钩子），但不要假装懂题材；必要时先向用户确认 |

**绝对不要**在本 skill 内：

- 另起角色名、改人物关系、改结局；
- 把其他 skill 的创作规则复制过来重新判断一遍；
- 因为格式放不下就删事件、删台词、跳段；
- 输出分析、创作说明、自检表、寒暄或 Markdown 代码围栏（除非用户明确要）。

## 三、工作模式

先判断用户要哪一种，只做一种：

| 模式 | 输入 | 输出 |
|---|---|---|
| `bridge`（默认） | 其他 skill 的剧本/大纲/段子 + 交付要求 | 可直接导入的 DirectorDeck 剧本 |
| `co-write` | 用户要求“和某 skill 一起写” | 创作由其他 skill 主导；本 skill 只补分段、台词长度、素材槽和格式 |
| `audit` | 已有剧本 | 问题清单 + 最小修改建议（不重写全文） |
| `convert` | JSON / H3 V6 / DirectorDeck 文本中的一种 | 用户指定的另一种格式 |

不要同时进行“创作”和“格式交付”两套脑内流程。创作阶段服其他 skill，交付阶段服本 skill。

## 四、和其他 skill 的交接协议

如果主 agent 正在编排多个 skill，建议按下面顺序交接：

1. **创作 skill** 先产出：
   - 故事前提、人物、每段事件/情绪/钩子；
   - 已有的角色名、重要道具、场景；
   - 用户指定的题材、文风、时长、段数。
2. **本 skill 接收后**只做：
   - 一段一个主要事件；
   - 对齐用户/其他 skill 给的总时长与段长；
   - 绑定素材槽（只使用已确认的槽位）；
   - 校验导入格式。
3. **不要反向重写创作稿**。如果发现剧情缺环，用最小补丁补一句过渡，并在交付后注明“补了过渡段/补了一句动作”，不要静默改主线。

详细交接字段见 `references/handoff-schema.md`。

## 五、输出格式（必须精确）

支持三种，详细正则、示例与限制见 `references/directordeck-formats.md`：

1. **DirectorDeck 文本（默认推荐）**
   ```
   第1段（5秒）
   [画面] 雨夜，女主撑伞站在台阶下 @图片1
   女主：你终于回来了。
   ```
2. **JSON 剧本**：`characters` + `segments`，段落字段 `seconds / scene / actions / image_refs / dialogue`。
3. **H3 V6 文本**：`【第N段｜X秒】` 段头 + `(S1) ... <d>台词</d>` + `<Picture N>`。

除非用户指定，否则默认输出 **DirectorDeck 文本**。不要输出 Markdown 代码围栏，不要把分析混进剧本正文。

## 六、交付规则（内容层的最小约束）

这些不是创作规则，是“能被 DirectorDeck 正常导入/生成”的硬约束：

1. **一段一个主要事件**；下一段起始状态 = 上一段结束状态。
2. **段头格式固定**：`第N段（X秒）`，全角括号；N 从 1 连续；秒数 1–60。
3. **对白行只写 `角色：台词`**，台词里不写动作、表情、镜头、语气说明；动作/运镜写到 `[画面]` 行。
4. **动作行开头不要出现“角色名：”**，否则会被导入器当成对白；需要写谁做什么时，用“女主撑伞走出门”而不是“女主：撑伞走出门”。
5. **台词长度**按段长压缩：3 秒 ≈ 9 个中文字以内，5 秒 ≈ 16 个以内，10 秒 ≈ 30 个以内（宁可拆句，不要赶）。
6. **角色名稳定**；对白行的角色名尽量不超过 12 个字符，避免冒号/空格。
7. **素材槽只使用已确认的 `@图片1` … `@图片9`**；数量不够时不要猜槽号，要么留空让导入器自动匹配，要么先问用户。素材槽和角色绑定后全篇保持一致。
8. **一次导入最多 64 段**；超过时拆成两个文件，不要截断剧情。
9. **不要编造 `@音频N` / `@视频N` 槽位**；需要锁音时另行按 VoiceLock/TTS 契约交付。
10. **全篇语言、角色名、图片槽号一致**。

## 七、交付前自检

尽量调用仓库里的独立校验器（不依赖 ComfyUI）：

```bash
python skills/directordeck-screenplay-bridge/scripts/validate_screenplay.py <剧本文件> --format auto
```

至少人工过一遍：

- [ ] 段头连续、秒数合法、段数 ≤ 64；
- [ ] 每段都有画面或台词，没有空段；
- [ ] 对白行都符合 `角色：台词`，动作行没有被写成对白；
- [ ] 台词数量/长度与段长匹配；
- [ ] `@图片N` 都在 1–9 且是用户确认过的槽；
- [ ] 没有 Markdown 围栏、分析、创作说明；
- [ ] 与其他 skill 的设定、角色、结局没有冲突；
- [ ] 导入节点 `format=自动识别` 时能被正确识别（JSON / V6 / DD 文本）。

## 八、最小输出模板

```text
第1段（5秒）
[画面] 场景、人物状态、主要动作、运镜，结尾停在可衔接的位置 @图片1
角色：一句短台词。

第2段（5秒）
[画面] 承接上一段结尾状态，发生下一个事件。
角色：台词。
```

如果用户同时要“人类可读版 + 导入稿”，先给导入稿，再给人类可读版，并明确标注。不要用人类可读版代替导入稿。
