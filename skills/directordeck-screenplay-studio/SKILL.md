# DirectorDeck 剧本工坊

这是一个**单 skill 覆盖创作 → 分段 → 交付 → 质检**的 DirectorDeck 专用剧本工坊。

它不是“提示词模板集合”，也不是 Seedance 投喂工具。最终产物只有一类：

> 能直接粘贴进 `DirectorDeck_ScriptImport`、并在 DirectorDeck 画布上跑起来的分段剧本。

## 一、何时使用

### 用

- 用户要写一个短剧/漫剧/情绪短片剧本，并且最终要交给 DirectorDeck 生成视频；
- 用户要把小说、梗概、大纲、外部剧本改成 DirectorDeck 可导入格式；
- 用户要在 `M13 剧本导入` / `M16 完整工作流` 里补剧本、补段、改某段、做续写；
- 用户明确提到 `DirectorDeck`、`剧本导入`、`ScriptImport`、`@图片N`、`分段生成`、`锁音`、`二次处理成片`；
- 用户要把已有剧本做**导入前质检**（段号/秒数/台词/素材槽/格式）。

### 不用

- 目标是 Seedance 2.5/2.0 投喂稿、七段式提示词、`图N` / `@CHR-` 体系；
- 只是闲聊剧情、写小说、写分镜，但没有 DirectorDeck 交付目标；
- 用户要求其他平台/媒介的格式（标准剧本 PDF、Excel 分镜表、动画分镜等）且不提 DirectorDeck。

如果用户既想要 Seedance 又想要 DirectorDeck：**拆两份交付**，本 skill 只负责 DirectorDeck 那份。

如果目录里同时有 **漫剧老李（`short-drama-director` + `sd-*`）** 或 **H3 V6 模板**，
按目标平台二选一，不要混：

- Seedance 投喂 / `图N` / 七段式 → 用漫剧老李，本 skill 不接管；
- DirectorDeck 导入 / `@图片N` / 第N段 → 用本 skill，不走 `sd-feed-engine`；
- 两边都要 → 出两份独立文件，不要在同一份稿里混用 `图N` 和 `@图片N`；
- H3 V6 模板只负责提示词本体；要导入 DirectorDeck 时由本 skill 解析/校验/转换；
- 目标不明确时先问“交付 Seedance 还是 DirectorDeck”，不要默认选边。

原因很简单：`sd-feed-engine` 的最高优先级术语口径禁用 `@图片N`，而 DirectorDeck 必须用 `@图片N`；
同一份稿不可能同时满足两个平台。

## 二、最终交付契约

默认输出 **DirectorDeck 文本**：

```text
第1段（5秒）
[画面] 场景，人物状态，主要动作，运镜；结尾停在可承接状态 @图片1
角色：一句能说完的台词。

第2段（5秒）
[画面] 承接上一段结尾状态，发生下一个事件。
角色：台词。
```

支持但非默认：

- **JSON 剧本**：`characters` + `segments`（字段见 `references/directordeck-delivery.md`）；
- **H3 V6 文本**：`【第N段｜X秒】` + `(S1) ... <d>台词</d>` + `<Picture N>`。

硬约束（导入器会校验）：

- **一段一个事件**：一段只解决一个主要事件，段尾必须能接下一段；
- 段头 `第N段（X秒）`，N 从 1 连续；秒数 1–60；段数 ≤64；
- 对白行 `角色：台词`，角色名 ≤12 字符；
- 动作/运镜放 `[画面]` 行，动作行开头不要写 `角色：`；
- `@图片N` 仅 1..9，且只使用已确认的素材槽；
- 不输出 Markdown 代码围栏、分析、自检表、寒暄混在正文里。

交付前尽量跑独立校验器：

```bash
python skills/directordeck-screenplay-studio/scripts/validate_screenplay.py 剧本.txt --format auto
```

## 三、开工前锁定（DirectorDeck 版）

缺的可以给默认值，但**用户明确说过的不许改**。不确定就问，不要替用户默认。

| 项 | 默认 | 说明 |
|---|---|---|
| 目标 | DirectorDeck 剧本导入 | 不确定就只问这一项 |
| 总时长 / 段数 | 按内容定；≤64 段 | 5 秒/段时，30 秒 ≈ 6 段 |
| 每段秒数 | 5 秒 | 1–60；短剧推荐 3/5/10 |
| 画幅 | 16:9 横屏 | 竖屏短剧用 9:16；方屏 1:1 |
| 分辨率 | 480p | 仅影响画面，不影响剧本格式 |
| 语言 | 中文 | 台词语言全篇一致 |
| 文风 / 类型 | 按用户 | 题材、年代、平台调性 |
| 角色 | 按故事 | 名字稳定；最多 9 个图片槽 |
| 素材槽 | 无/自动匹配 | 有图就绑定 `@图片1..9`；没有就不写 |
| 声音 | H3 原声 | 需要 TTS/锁音时，另给角色音色/CAST |
| 连续性 | `latent_tail` / 相邻段承接 | 多段链必须段段能接 |
| 交付格式 | DirectorDeck 文本 | 用户要 JSON/V6 才换 |

把这些写在回复开头的一句话即可，例如：

> 交付：DirectorDeck 文本 / 6 段 × 5 秒 / 9:16 / 角色 2 人 / 素材槽 1–2 / 中文。

## 四、六阶段流程

### 阶段 0：定方向（不写正文）

- 一句话故事（logline）：谁 + 想要什么 + 被什么阻止 + 代价；
- 平台/受众/时长/画幅/类型；
- 结尾是反转、爽点还是悬念；
- 哪些内容必须保留（用户给的原台词/名场面/结局）。

### 阶段 1：故事脊柱

- 初始状态 → 触发事件 → 第一次行动 → 升级/反转 → 高潮 → 结尾；
- 只留一条主线；支线不能挤占主线段落；
- 明确“每段结束时，观众多知道了什么/更担心什么”。

### 阶段 2：人物与资产圣经

每个角色至少写清：

- 身份、欲望、阻力、秘密/缺陷、与其他人的关系；
- 固定外形/服装/标志物（AI 生成要保持一致）；
- 固定音色描述（如果要用 TTS/锁音）；
- 绑定素材槽（如果素材库有图）。

同时列出**场景清单**和**道具清单**：

- 场景：空间、时间、天气、光线、出入口；
- 道具：谁持有、在哪些段出现、状态怎么变化；
- 资产只使用确认过的 `@图片N`，不要猜编号。

### 阶段 3：分段计划表

写完整剧本前，先出这张表（人类可读即可）：

| 段 | 秒 | 场景 | 事件（只一个） | 情绪/信息变化 | 画面与动作 | 台词要点 | 素材 | 段尾钩子 |
|---|---|---|---|---|---|---|---|---|
| 1 | 5 | 老宅台阶/雨夜 | 女主等男主 | 期待→紧张 | 撑伞、门内脚步声、镜头缓慢推近 | “你终于回来了。” | @图片1 | 门开一半停住 |
| 2 | 5 | 门口 | 男主出现 | 紧张→克制 | 男主走出、两人对视、镜头反打 | “这十年，我一直在找你。” | @图片1/2 | 女主后退半步 |

规则：

- 一段只解决**一个主要事件**；
- 下一段开头 = 上一段结尾状态；
- 第 1 段前 3 秒必须有钩子（异常、冲突、悬念、强情绪）；
- 连续纯对白不超过 2 段，第三段必须加动作/画面变化；
- 每段至少有一个视觉变化（走位/景别/动作/光线）。

### 阶段 4：写正式剧本

按锁定格式写。写作时永远问自己：

1. 这一段观众看到/听到了什么新信息？
2. 这一段结束时状态发生了什么变化？
3. 下一段能不能直接从这一段的最后一帧接上？
4. 台词能不能在秒数内自然说完？

详细创作规则见 `references/short-drama-craft.md`。

### 阶段 5：润色与质检

- 台词口语化：去掉解释性台词、书面语、重复信息；
- 动作可拍：写清谁、什么状态、做什么、停在哪；
- 连续性：服装/道具/伤口/天气/时间/站位/视线方向；
- 台词长度按段长压缩；
- 跑校验器 + 人工过 `references/qc-checklist.md`。

### 阶段 6：交付

1. 给最终剧本正文（默认 DD 文本）；
2. 给可选的“角色 → 素材槽 → 音色”对照表；
3. 说明已做的压缩/拆分（如果动过台词长度）；
4. 画布操作：粘贴进「剧本导入」→ 接素材库 → 面板「按剧本建生成器」→ 运行 → 预览 → 手动合并 → 二次处理成片。

## 五、DirectorDeck 5 秒段的硬写法

| 段长 | 台词上限 | 画面/动作 | 建议镜头 |
|---|---|---|---|
| 3 秒 | ≤9 字 | 一个动作/一个反应 | 一个固定机位或一次快速推近 |
| 5 秒 | ≤16 字 | 一个主要动作 + 一次变化 | 一个主要运镜 |
| 10 秒 | ≤30 字 | 可有两拍，但只一个事件 | 一次运镜 + 一次反应 |

- 一段最多一个主要说话人；对话多就拆到相邻段；
- 台词里不写“小声/冷笑/看向他/推近”等表演/镜头说明，这些放 `[画面]`；
- 一段只安排一个主要运镜（推/拉/摇/移/升降/手持，选一个主运动）；
- 需要观众看清表情时用近景/中近景，不要用远景承担表演；
- 连续段保持同一空间轴线，不要无故跳轴。

## 六、动作/打戏段（精简版）

DirectorDeck 的动作段同样按“一段一事件”拆，不要试图在 5 秒里塞完整打斗：

- 先定：谁要什么、谁阻止、力量差在哪、环境怎么参与；
- 每段只写一个动作回合：起势 → 接触/闪避 → 结果 → 反应；
- 5 秒段最多 2–3 个动作节拍；超过就拆段；
- 写清受力结果（退几步/撞到什么/武器脱手），不要只写“打得很激烈”；
- 真实/写实向要克制，玄幻/仙侠向可写能量/法术，但都要有可见结果；
- 避免平台高风险细节（断肢/血腥特写等），用结果和反应替代。

## 七、资产与声音

### 图片槽（1–9）

- 槽位固定：`@图片N` 对应素材库第 N 槽；
- 同一角色全篇用同一槽；不同身份角色不要复用同一张图；
- 没有槽/没图时不要写 `@图片N`，让导入器按名字自动匹配；
- 场景/道具也可以占槽，但要在对照表说明；
- 参考图不够时，先报告缺口，不要猜。

### TTS / 锁音

- 需要 TTS 时，角色名必须和 `TTSBooth`/`VoiceLock` 的角色名一致；
- 台词要适合 TTS：短句、少生僻字、避免括号/符号堆叠；
- 需要锁音/口型时，另给“角色 @起始秒 | 音色 | 台词”的台词表；
- 音频槽和图片槽是两套编号，不要混。

## 八、质检与返工

交付前必须过：

- [ ] 段头连续、秒数 1–60、段数 ≤64；
- [ ] 每段一个事件，段间状态能接；
- [ ] 台词符合 `角色：台词`，长度能说完；
- [ ] 动作行没有被写成对白；
- [ ] `@图片N` 合法且是确认过的槽；
- [ ] 没有 Markdown 围栏/分析/说明混入正文；
- [ ] 角色、服装、道具、场景、时间线没有矛盾；
- [ ] 用户明确要求保留的内容没有被改。

校验器：

```bash
python skills/directordeck-screenplay-studio/scripts/validate_screenplay.py 剧本.txt --format auto
python ... 剧本.json --format json
python ... 剧本.txt --format v6
```

退出码 0 = 无 error（可以有 warning）。发现问题按“最小修改”返工，不重写整篇。

## 九、和 DirectorDeck 画布的衔接

推荐用 M16 完整工作流：

1. 把最终剧本粘贴到 `DirectorDeck_ScriptImport.script`，`format=自动识别`；
2. 有参考图就接 `DirectorDeck_AssetShelf`，保持槽位与剧本一致；
3. 点面板 **按剧本建生成器**，按段数自动建/接生成器；
4. 点 **补全合并输出**（或手动接合并器）；
5. 运行，逐段看节点预览；不满意可点生成器上的 **再次生成本段**；
6. 满意后点合并器 **手动合并本片**；
7. 点二次处理成片 **生成最终视频**（二采 / RelayVSR / 二采 LoRA）。

剧本字段与画布节点参数的对应关系、导入参数、JSON/V6 细节见
`references/directordeck-delivery.md`。

## 十、禁止事项

- ❌ 不要输出 Seedance 七段式投喂稿、`图N`/`@CHR-`/`@SCN-` 体系；
- ❌ 不要把 `图N` 和 `@图片N` 混在同一份稿；
- ❌ 不要用 Markdown 代码围栏包剧本；
- ❌ 不要在剧本正文里写创作说明/自检表；
- ❌ 不要为了“看起来高级”堆形容词、堆镜头术语；
- ❌ 不要删用户明确要求保留的台词/事件/结局；
- ❌ 不要凭空增加角色/支线/场景/道具/素材编号。
